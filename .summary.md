## Objective

Build an *E. coli* protein-solubility prediction tool using a protein language
model plus confidence-aware ESMFold structural features, with explicit
surface/exposure and hydrophobic-patch modeling.

The scientific emphasis is:

- quantitative eSOL supervision as the high-quality endpoint;
- large binary weak supervision from UESolDS and PDBSol;
- dataset-specific heads because the label endpoints are not interchangeable;
- mesh-free surface-patch encoding rather than only a generic C-alpha GNN;
- strict homology-held-out evaluation using exhaustive Biopython pairwise SI;
- provenance for every observation, including repeated/conflicting measurements.

## Fixed data policy

Do **not** globally deduplicate or remove similar proteins for training. Retain:

- similar sequence variants;
- identical sequences from different datasets;
- repeated measurements;
- conflicting labels as separate source observations.

Use one canonical sequence entity (SHA-256) for similarity computation. Every
source observation points to an entity. If two entities have Biopython pairwise
SI `>=30%`, connect them; every connected component must be assigned wholly to
one of train/validation/test. Thus SI is a split constraint, not a deletion rule.

For a frozen eSOL benchmark, PDBSol/UESolDS observations homologous to eSOL
validation/test remain in the corpus but must inherit the held-out component and
must not reach the optimizer.

Current provisional SI definition in `DOCs/architecture.md` is global alignment,
identical aligned residue pairs divided by alignment columns including gap
columns. Before the long run, freeze exact match/mismatch/gap scores and verify
that this matches the intended historical “Inter_Protein SI 30% Gap” definition.

- one process: about 1,318 pairs/s;
- 128 processes: about 95,122 pairs/s;
- 256 processes: about 105,000 pairs/s.

30–40 hours for length skew, NUMA, checkpoints and output.

A packed float32 triangular matrix is approximately 35 GB. The current disk could
hold it, but future ESMFold structures/features plus checkpoints justify migration.
After migration, run exhaustive Biopython without MMseqs/CD-HIT candidate filtering.

## Required SI engine before starting the long job

Implement and test a block-wise, multiprocessing SI engine with:

- canonical entity input ordered deterministically by sequence SHA-256;
- immutable run config containing Biopython version and every scoring parameter;
- packed triangular float32 or a clearly documented fixed-point representation;
- block checksums and atomic completion markers;
- resume after interruption without recomputing completed blocks;
- NUMA-aware worker placement (benchmark 128 physical-core workers versus 256);
- online union-find updates for SI>=30% edges;
- nearest-neighbor/top-cross-split audit records;
- small exhaustive correctness tests against a straightforward implementation;
- explicit handling of multiple optimal global alignments so the denominator rule
  is deterministic and reproducible.

Do not launch the 30–40 hour production computation before these invariants and
checkpoint recovery are tested.

## Model plan

Recommended staged model:

1. PLM-only baselines: ESM-C/ESM-2 mean pooling and attention pooling.
2. Structure descriptors: ESMFold pLDDT, RSA/SASA, packing/contact density,
   secondary structure and exposed/buried ratios.
3. Geometry-aware residue encoder plus confidence gating and structure dropout.
4. Mesh-free surface-patch pooling for exposed hydrophobic patches, exposed charge
   and local charge clustering.
5. UESolDS/PDBSol weak binary pretraining with dataset-specific heads.
6. eSOL continuous regression plus derived classification fine-tuning.

Never feed PDB similarity, source identity or “maximum identity to E. coli PDB” as
a predictive feature. Source metadata is for heads, sampling, auditing and domain-
shift evaluation, not a shortcut input at deployment.

## Migration procedure

Choose a destination with at least several hundred GB free; 1 TB free is preferred
if PDB structures, ESMFold outputs and multiple feature revisions will be retained.
Do not start long-running extraction before the move.

Recommended copy pattern after the destination mount/path is known:

```bash
rsync -aHAX --info=progress2 /home/pc/Code/PLS/ /destination/PLS/
```

The trailing slashes matter. Do not delete the source yet. Verify at destination:

```bash
du -sh /home/pc/Code/PLS /destination/PLS
sha256sum /destination/PLS/preparation/raw/esol.zip
sha256sum /destination/PLS/preparation/raw/PLM_Sol-V1.1.zip
sha256sum /destination/PLS/benchmark/generated/fgnnsol_esol_manifest.csv
sha256sum /destination/PLS/benchmark/generated/uesolds_observations.csv
for d in FGNNSol SurfSol ProtSolM ProSolNet; do
  git -C "/destination/PLS/preparation/external/$d" fsck --no-dangling
done
```

Then rerun the two manifest builders and confirm their hashes:

```bash
python preparation/audit_benchmarks.py \
  --fgnnsol preparation/external/FGNNSol \
  --surfsol preparation/external/SurfSol \
  --output benchmark/generated/fgnnsol_esol_manifest.csv

python preparation/normalize_uesolds.py \
  --input-dir preparation/raw/uesolds \
  --output benchmark/generated/uesolds_observations.csv
```

Only after byte-level verification and a successful continuation from the new
working directory should the old copy be considered for removal.
